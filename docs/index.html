SystemLens

Architecture context, kept local.

SystemLens gives coding agents source-evidenced Java/Spring architecture context before they change a system. It indexes REST, Kafka, build projects, OpenAPI, MongoDB, and explicit architecture facts into a local SQLite snapshot.

Quick start

At the root of a Java/Spring repository, run systemlens init, systemlens doctor, and systemlens index. Use systemlens mcp for an agent workflow, or export an interactive graph with systemlens export microservices --html architecture.html.

Use SystemLens with a coding agent

systemlens-skill gives a coding agent a disciplined, evidence-first workflow. It starts from the local SystemLens inventory, makes blind spots explicit, and keeps any AI-enriched architecture facts separate from source-derived facts.

npx skills add elkouhen/systemlens-skill
uv tool install systemlens

# In the Java/Spring repository you want to understand
systemlens init
systemlens doctor
systemlens index

# Have the agent write reviewable, relative-evidence facts in JSON.
# Import the facts into the AI architecture namespace.
systemlens import-facts architecture.ai-graph.pass-001.json \
  --namespace ai-architecture
systemlens export microservices --html architecture.html
1. IndexInstall the skill, then initialize and index the repository locally.
2. DescribeHave the agent inspect source evidence and write a JSON facts manifest for what needs enriching.
3. ImportImport the reviewed manifest into its own namespace; source-derived facts remain unchanged.
4. ExportGenerate the merged architecture graph for review or handoff.

For a focused question, the agent can write only the relevant facts. For a full topology, it can work in boundaries, HTTP, messaging, data, and deployment passes. Each pass is replaceable and keeps dynamic or unresolved integrations visible instead of guessing them.
